# NBA DFS Engine

## Core Philosophy
NBA DFS is highly role- and news-sensitive. Minutes, usage, starting status, rotation changes, pace, and game environment should drive adjustments more than static season-long averages.

## Required Checks
- confirmed starters and injury statuses
- projected minutes and role
- usage / assist / rebound changes from absences
- spreads, totals, and implied team totals
- pace and matchup environment
- projected ownership
- late swap opportunities

## Portfolio Construction
Balance ceiling and ownership while avoiding accidental overexposure to fragile value created by uncertain rotations. Correlate game environments selectively; not every NBA lineup needs a full game stack.

For large-field builds, use differentiated but plausible combinations rather than simply maximizing median projection.

## User Construction Defaults
For NBA main slates, three uniques may be used as a default portfolio diversification setting when appropriate. Secondary/turbo slates may use a more diversified construction style.

## Exposure Audit
Every final lineup set must include source projected ownership vs DFS Engine exposure with percentage-point difference and the rationale for meaningful deviations.
